## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan Fidelity | The diff read against the plan's scope and deviation notes | Every changed file and logic change falls inside the plan's boundary or explicit deviation notes. The description does not claim more or less than the diff delivers. | required |
| Test Evidence | The test evidence read against the plan's test plan and the repo's checks | It shows the before/after results on an observable behavior AND shows the outcomes of the repo's required automated checks (make test-unit, etc.). | required |
| Diff Quality | The diff and the commit list | The fix is cleanly visible without unrelated ride-along changes, debug debris, or commented-out dead code. | required |
| Standards and Comms | The description read against the repo's template asks and stated policy | The description fills the template sections with real content, explicitly discloses AI usage if required, and engages any maintainer direction. | required |

## Verdict rule

<!-- State how the grades above combine into accept or reject, and how

Accept (submit) if every required check passes. Reject (hold) if any required check fails. If any required check is graded `unclear`, it counts as a fail.
